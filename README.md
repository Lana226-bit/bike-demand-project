# BikeSochi: прогнозирование спроса на велопрокат

Проект по прогнозированию почасового спроса на аренду велосипедов в Сочи
на основе погодных и календарных данных. Baseline-модель линейной регрессии
заменена на нелинейную модель, которая учитывает сложные зависимости между
погодой и спросом.

## Задача

Компания BikeSochi использовала линейную регрессию для прогноза спроса.
Модель не различала ситуации «+28 °C под солнцем» и «+28 °C после дождя»,
поэтому часто ошибалась. Цель проекта — предложить более гибкую модель,
которая снизит ошибку прогноза.

**Целевая переменная:** `Rented Bike Count` — количество велосипедов,
арендованных за час.

**Основная метрика:** RMSE. Дополнительные — MAE, R².

**Условие успеха:** финальная модель должна превзойти baseline по RMSE.

## Данные

- 7008 наблюдений, 16 признаков.
- Погодные: температура, влажность, скорость ветра, видимость, точка росы,
  солнечная радиация, осадки, снег.
- Календарные: сезон, праздник, функционирование станции, время суток
  (4 бинарных интервала).
- Пропуски (~4%) в шести метеопараметрах заполнены медианами по сезону
  и по сезону + времени суток.

## Подход

**1. EDA.** Изучены распределения, сезонность, зависимости спроса от
температуры, осадков, радиации. Проверена PhiK-корреляция признаков
с целевой переменной.

**2. Feature engineering.** Созданы признаки:
- `is_rain`, `is_snow` — бинарные флаги осадков (PhiK с целью в 9 раз выше,
  чем у исходных `Rainfall` и `Snowfall`).
- `is_sunny` — флаг солнечности (радиация > 0.35).
- `temp_sunny` — произведение температуры и флага солнца.
- `temp_category` — категориальная температура (Freezing/Cold/Mild/Warm/Hot)
  с порогами 0, 10, 20, 28 °C. PhiK = 0.639 с целевой — выше, чем у самой
  `Temperature` (0.603).
- `is_bad_weather` — агрегат «дождь или снег или сильный ветер».

**3. Модели.**
- Baseline — линейная регрессия (предоставлена компанией).
- kNN — 3 варианта набора признаков (main / full / minimal).
- DecisionTreeRegressor — 2 варианта (main / full).

**4. Оптимизация.** Подбор гиперпараметров через Optuna. Единая схема
кросс-валидации `KFold(n_splits=5, shuffle=True, random_state=42)` для
честного сравнения всех моделей.

**5. Финальная проверка.** Лучшая модель обучена на всей train-выборке
и один раз проверена на отложенном тесте.

## Результаты на тестовой выборке

| Модель | RMSE | MAE | R² |
|---|---|---|---|
| Baseline Linear Regression | 411.56 | 312.60 | 0.586 |
| **Tree (main) — финальная** | **311.81** | **205.50** | **0.762** |

**Улучшение относительно baseline:** −24.2% по RMSE, −34.3% по MAE,
R² вырос с 0.586 до 0.762.

## Финальная модель

**DecisionTreeRegressor** с гиперпараметрами:

- `max_depth = 12`
- `min_samples_split = 51`
- `min_samples_leaf = 7`
- `max_features = 1.0`
- `ccp_alpha = 0.80`
- `random_state = 42`

**Почему именно она:**
- лучший RMSE и MAE на CV и тесте среди всех моделей;
- приемлемая стабильность (RMSE_std = 7.64, сопоставим с разницей между моделями);
- высокая интерпретируемость — можно построить конкретные правила
  «если … то …» и защитить перед бизнесом;
- не требует масштабирования признаков, что упрощает внедрение.

**Почему не kNN:** чуть выше RMSE, менее интерпретируем, требует
масштабирования.

**Почему не baseline:** линейная регрессия не улавливает нелинейные
зависимости (оптимум спроса при +24…+28 °C, падение при экстремальной жаре)
и не различает пиковые и обычные дни.

## Важность признаков

Топ-5 для дерева (встроенная `feature_importances_`):

| Признак | Важность |
|---|---|
| Temperature | 33.0% |
| Time_Period_Night | 17.2% |
| Humidity(%) | 13.2% |
| Functioning Day | 9.5% |
| Time_Period_Evening | 8.8% |

Для kNN (permutation importance) важности распределены равномерно:
`Seasons`, `temp_category`, `Humidity`, `Wind speed`, `Solar Radiation`.
`Dew point temperature`, `Rainfall(mm)`, `Snowfall (cm)` — в самом низу,
что подтверждает их избыточность.

## Ключевые бизнес-выводы

1. **Температура — главный драйвер спроса.** Оптимум при +20…+28 °C,
   при экстремальной жаре (>28 °C) спрос падает, при морозе — минимален.
2. **Время суток критично.** Вечерний пик (16:00–19:59) и ночной минимум
   (00:00–05:59) отличаются в 4–5 раз. Это прямо влияет на распределение
   парка между станциями.
3. **Влажность важна.** Высокая влажность снижает спрос даже при
   комфортной температуре — значимо для приморского климата Сочи.
4. **Осадки важны как факт, а не как количество.** Достаточно флага
   «дождь / снег / плохая погода» — точные миллиметры не нужны.
5. **Сезонность.** Летом спрос почти в 5 раз выше зимнего. Парк нужно
   масштабировать по сезону.
